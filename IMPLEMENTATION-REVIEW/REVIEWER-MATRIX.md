# Reviewer Matrix

This matrix identifies the expertise requested for independent review. It is not a ranking of individuals.

| Area | Required expertise | Primary questions |
|---|---|---|
| Protocol architecture | Distributed protocol engineering | Determinism, boundaries, interoperability |
| Bitcoin | Bitcoin protocol engineering | Transaction model, UTXO interaction, verification |
| Lightning | Lightning protocol/infrastructure | Channels, settlement, failure handling |
| Cryptography | Applied cryptography | Signatures, commitments, key management |
| Mental Poker | MPC / ZK / private-card cryptography | Dealer security, shuffle, reveal |
| CID / Logs | Cryptographic data structures | Hash chains, fragmentation, Merkle structures |
| P2P | Distributed systems / networking | Synchronization, peers, partitions |
| Consensus | Distributed consensus | Agreement and conflict resolution |
| Poker | Deterministic poker-engine development | Rules, betting, side pots, replay |
| Security | Protocol security auditing | Threat model and adversarial testing |
| Formal verification | Formal methods | State-machine and invariant verification |
| Testing | Property-based / differential testing | Cross-implementation convergence |
| Systems | Rust / systems engineering | Reference implementation and reliability |
| UI | Protocol-aware client engineering | Separation of presentation from protocol |

## Desired reviewer profile

The strongest review panel is multidisciplinary. A single person should not be expected to validate every layer of CPG.
