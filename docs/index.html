Protocol

CPG / SPECIFICATION

Protocol architecture

Chain Poker Genesis is an implementation-independent protocol project for formalizing decentralized poker as a precise, testable and interoperable system.

The protocol separates game rules from network behavior, cryptographic verification, event history, state management and settlement. Implementations can evolve without silently changing the underlying protocol.

CORE PRINCIPLES
  • Deterministic execution
  • Explicit state transitions
  • Cryptographic verification
  • Commitment & reveal
  • Distributed event history
  • Replayable state
  • Modular engines
  • Independent implementations
02

A Player's First Hand

A short narrative showing how the protocol can be experienced from the player's side, from installation to the beginning of a first hand.

PLAYER EXPERIENCE · CPG / GENESIS

The player begins with the installer. There is no table yet, no cards and no hand to play. There is only a package containing the software required to participate in the network.

After downloading it, the player installs the node. The installation process prepares the local environment, creates the necessary identity and configuration, and makes the machine capable of communicating with the protocol.

When the application opens, the player is not simply connected to a website. The local installation becomes a participant in a protocol. It discovers or establishes the connections required by the network and begins preparing the state it needs to operate.

The player then creates or loads the wallet environment used by the installation. Before money is committed to a game, the player can inspect the available configuration, the table rules and the conditions under which value will move.

Next comes the table. The player selects an available table or follows an invitation and sends a join request. The table verifies that the request satisfies its protocol conditions. If accepted, the player becomes a participant in the table state.

The table wallet and settlement layer prepare the value required for play. The player is not merely trusting a screen showing a balance: the relevant state and transitions are processed according to the protocol's defined rules.

Before cards can become part of the hand, the cryptographic dealing process begins. Commitments are established before the corresponding information is revealed. The purpose is simple: no participant should be able to silently rewrite the history after learning information that should have remained hidden.

The table reaches the state in which the first hand can begin. Players are identified in the table state, positions are established, the required balances are available, and the dealing mechanism is ready.

Then the first cards are dealt according to the protocol. The player sees the beginning of a poker hand, but underneath that familiar moment is a chain of state transitions, messages, commitments, validations and recorded events.

The first hand has started. From the player's perspective, it feels like poker. From the protocol's perspective, every meaningful step has become part of a verifiable state.
